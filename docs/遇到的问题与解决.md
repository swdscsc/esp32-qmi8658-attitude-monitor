## 问题 1：传感器上电初期读不到正确的设备 ID

- **现象**：单板复位后立即读 `WHO_AM_I`，偶尔读不到 `0x05`，后续寄存器配置全部失效。
- **排查**：把读取时序单独打印出来，发现上电瞬间 I2C 总线上从机尚未完成内部初始化。
- **原因**：QMI8658 上电后需要一段稳定时间，主机发起通信过早会读回无效值。
- **解决**：在 `Qmi8658_Init()` 中用循环反复探测 ID，并在每次探测之间延时，
  只有读到 `0x05` 才继续往下配置：

  ```c
  while (ID != 0x05) {
      vTaskDelay(1000 / portTICK_PERIOD_MS);
      qmi8658_register_read(QMI8658_WHO_AM_I, &ID, 1);
  }
  ```
- **延伸**：同类思路也用于复位之后 —— 写 `0xB0` 软复位后必须延时等待，不能立即写配置寄存器。

## 问题 2：连续读取 6 轴数据时拿到无效值

- **现象**：直接连续读 12 字节加速度/陀螺仪寄存器，偶尔得到明显偏离的异常数据。
- **排查**：回到数据手册查状态寄存器，确认 `STATUS0` 中存在数据就绪标志位。
- **原因**：传感器未完成一次完整采样时，寄存器中的值是上一次的残留或不确定值。
- **解决**：读取前先查 `STATUS0` 的低两位，确认数据就绪后再发起读取：

  ```c
  qmi8658_register_read(QMI8658_STATUS0, &status, 1);
  if (status & 0x03) {
      qmi8658_register_read(QMI8658_AX_L, (uint8_t*)buf, 12);
  }
  ```

## 问题 3：I2C 通信不稳定 / 设备扫描不到

- **现象**：I2C 扫描时有时找不到 `0x6A` 设备。
- **排查**：检查 SDA/SCL 硬件连接与上拉情况。
- **原因**：I2C 总线要求 SDA/SCL 必须有上拉电阻，缺少上拉时信号边沿不达标。
- **解决**：在 `IIC_Init()` 中启用 ESP32 内部上拉：

  ```c
  i2c_conf.scl_pullup_en = GPIO_PULLUP_ENABLE;
  i2c_conf.sda_pullup_en = GPIO_PULLUP_ENABLE;
  ```

- **备注**：若仍不稳定，建议改为外部 4.7 kΩ 上拉，并用示波器/逻辑分析仪观察 SCL/SDA 波形。
